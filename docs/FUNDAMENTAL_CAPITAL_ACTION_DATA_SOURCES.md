# 预披露与资本行为数据源方案

> 版本：v1.2
> 核验日期：2026-07-25（Asia/Shanghai）
> 用途：为 Fourseasquant 基本面模块接入公告预披露与资本行为数据。
> 适用范围：A 股沪深主板、创业板、科创板；实际入库时仍按项目股票池规则过滤。

## 1. 结论

巨潮资讯作为公告和资本行为主数据源，沪深交易所作为董监高股份变动的官方交叉核验源。

- 公告、预约披露、股本变动、实际控制人持股、高管持股、分红和配股：优先使用巨潮资讯。
- 董监高人员股份变动：以上交所、深交所页面为官方交叉核验源。

公募基金重仓和机构持股比例不属于本项目核心林奇机械规则。它们不能可靠表达“公司是否被市场忽视”，因此第一版不采集、不展示、不评分。兼容字段继续保持空值，避免破坏历史快照和既有 API。

## 2. 已核验的资本行为接口

本机 AKShare 版本为 `1.18.70`。2026-07-25 真实联网测试：

- `stock_hold_management_detail_cninfo(symbol="增持")` 可返回巨潮高管持股变动明细。
- `stock_hold_control_cninfo(symbol="全部")` 可返回实际控制人持股变动。
- `stock_hold_change_cninfo(symbol="全部")` 可返回公告日、变动日、变动原因及股本结构。
- `stock_zh_a_disclosure_report_cninfo(...)` 可按股票、日期、关键词和公告类别查询巨潮公告。
- `stock_share_hold_change_sse(symbol)` 与 `stock_share_hold_change_szse(symbol)` 可查询沪深交易所董监高股份变动。

## 3. 数据源映射

| 业务事实 | 主数据源与接口 | 备用/核验源 | 口径与限制 |
|---|---|---|---|
| 财报预约披露 | 巨潮 `stock_report_disclosure` | 交易所披露日历 | 预约日期不是财报事实可用日期 |
| 普通公告 | 巨潮 `stock_zh_a_disclosure_report_cninfo` | 沪深交易所公告 | 入库公告标题、时间、链接和内容哈希 |
| 高管增减持 | 巨潮 `stock_hold_management_detail_cninfo` | `stock_share_hold_change_sse`、`stock_share_hold_change_szse` | 必须区分主动现金交易与股权激励、继承、非交易过户等 |
| 实际控制人变化 | 巨潮 `stock_hold_control_cninfo` | 权益变动报告书 | 结构化结果仍需公告原文佐证 |
| 股本变化 | 巨潮 `stock_hold_change_cninfo`、`stock_share_change_cninfo` | 交易所公告 | 用变动原因区分增发、配股、转股、送转、回购注销 |
| 分红 | 巨潮 `stock_dividend_cninfo` | 权益分派公告 | 同时保存方案公告日与实施日 |
| 配股 | 巨潮 `stock_allotment_cninfo` | 配股实施公告 | 保存配股前后股本、实际配股数和上市日 |
| 回购及注销 | 巨潮公告，关键词“回购”“注销” | 股本变动记录、交易所公告 | 回购计划和未注销回购不能作为已注销回购 |
| 增发、股权激励、解禁、可转债 | 巨潮公告分类查询 | 股本变动记录、交易所公告 | 公告事件与实际生效事件分开存储 |

## 4. “预公告”的三种含义

实现前必须在字段名中明确具体含义：

- 财报预约披露：使用 `stock_report_disclosure`，保存首次预约、历次变更和实际披露日期。
- 巨潮“预披露”市场：主要是发行上市等预披露信息，不等于所有资本行为的提前公告。
- 业绩预告或资本行为公告：使用普通沪深京公告查询，并按 `业绩预告`、`增发`、`配股`、`股权激励`、`解禁`、`可转债`、`股权变动` 等类别过滤。

## 5. 资本行为评分的取数规则

当前项目需要的结构为：

- `insider_net_purchase_amount`
- `cancelled_buyback_amount`
- `newly_issued_shares`
- `shares_before_issuance`

建议按以下规则计算：

### 5.1 内部人士净交易额

只纳入能够确认是主动现金买卖的交易：

```text
净交易额 = Σ(增持股数 × 成交均价) - Σ(减持股数 × 成交均价)
```

股权激励、期权行权、分红送转、继承、司法过户等不得按主动现金增持计分。缺少成交均价时保留事件，但不推算金额。

### 5.2 已完成并注销的回购

必须同时满足：

1. 公告表明回购已经完成；
2. 公告或后续股本变动表明相关股份已注销；
3. 金额能够从公告原文追溯。

只有回购计划、仍在回购专户、用于员工持股或股权激励的股份不计入。

### 5.3 股本稀释

从股本变动和相关公告中识别增发、配股、可转债转股等新增股份：

```text
稀释比例 = 新增股数 / 发行前股数
```

送股、资本公积转增和股份拆细需要单独分类，不能无条件当作外部融资稀释。

## 6. 防止未来数据泄漏

每条事实至少保存：

- `report_period`：报告期；
- `announcement_at`：公告公开时间；
- `effective_date`：行为生效或股份变动日期；
- `source_name`、`source_url`、`source_record_id`；
- `content_hash`：公告内容哈希；
- `fetched_at`：抓取时间；
- `raw_payload_path`：本机原始快照路径。

任何日期为 `as_of_date` 的策略或基本面快照，只能使用 `announcement_at <= as_of_date` 的事实。预约披露日期不能提前激活尚未发布的财报数据。

## 7. 推荐实施顺序

已完成：

1. 巨潮高管增减持、逐股股本变动和回购公告采集；
2. 主动现金交易、外部融资稀释、注销式回购的保守归类；
3. 事件来源、结构化原始载荷、内容哈希和采集时间入库；
4. 最近十二个月聚合、平均流通市值归一化和真金白银信号分接线；
5. 完整批次原子发布、失败状态、逐股证据 API 和前端展示。
6. 从 AKShare 返回的巨潮公告详情链接解析官方 PDF，并机械提取金额与股数。

后续增强：

1. 接入财报预约披露；
2. 用沪深交易所董监高变动数据做第二来源交叉核验；
3. 为管理层交易补充逐公告直达链接；
4. 基本面研究模块交付版本化成员关系后，计算同行百分位。

注销式回购只有在巨潮官方注销完成公告 PDF 同时提供可核验注销金额与注销股数，
且能够按股票、公告时间窗口一对一匹配回购记录时才计分。一条官方公告
不能重复确认多轮回购；只有东方财富汇总金额或只有注销标题时均保留证据但
不进入评分。

PDF 解析失败、字段缺失或与本轮回购汇总不能一一对应时，该事件保留为待
核验证据，评分保持为零。

下载成功的官方 PDF 按 SHA-256（安全哈希算法）内容哈希永久保存到
`data/raw/cninfo/`；事件原始载荷同时记录官方文件网址、哈希和本机路径。
单份 PDF 下载或解析失败只写入该公告的核验错误，不会让整只股票或全批失败。

巨潮高管增减持接口的最近一年窗口由运行日决定。为防止历史补跑缺段仍被
标记为完整，资本行为批次当前只允许发布到数据库最新正式行情日；更早日期
必须等待可显式指定起止日期的官方数据源。

即使目标日是最新行情日，只要采集运行日与目标日不同，高管增减持项也会
标记为窗口未知并禁止计分，金额、比例和调整分均为空值；股本稀释和回购注销仍按各自可验证证据计算。
发布事件本身严格截取目标日前十二个月，股本变动的更早记录仅在内存中用作
计算期初股本基线，不进入批次和前端。
