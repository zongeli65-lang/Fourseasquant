# 四海量化个人基本面系统：前端工程交接

## 1. 交付目标

将现有“个人四支柱基本面机械系统”接入四海量化前端，使用户可以查看：

1. 东方财富板块候选池及其股票。
2. 个股月度基本面结果。
3. 彼得·林奇机械指标。
4. 利润贡献最高的主营业务。
5. A股流通市值及全市场百分位。
6. 东方财富股吧与雪球的每日讨论热度和情绪。
7. 数据日期、规则版本、证据状态和缺失原因。

本系统不是专业证券研究系统，不生成目标价、投资建议或“基本面总分”。第一版必须保持纯机械化，不得在展示链路中调用 Agent（智能体）。

## 4. 页面范围

### 4.1 基本面总览页

总览页至少包含：

- 股票搜索。
- 板块候选池选择。
- 板块内股票列表。
- 月度基本面数据日期。
- 每日舆情数据日期。
- 流通市值及百分位。
- 主营业务名称及利润贡献比例。
- 调整后市盈率。
- 林奇增长估值比。
- 舆情热度百分位。
- 综合情绪值。
- 数据完整性状态。

总览页可以排序和筛选，但不得擅自合成“基本面总分”。

### 4.2 个股基本面详情页

详情页按四个支柱分区。

#### 支柱一：彼得·林奇机械数据

展示：

- 普通滚动十二个月市盈率。
- 调整后滚动十二个月市盈率。
- 市盈率历史百分位。
- 市盈率同行百分位。
- 最近五个完整年度的调整后每股收益。
- 每股收益增长率及稳定性。
- 林奇增长估值比。
- 每股净现金。
- 扣除净现金后的市盈率。
- 资产负债率或债务权益比。
- 短期债务和长期债务。
- 股息率、派息率、连续分红和增长状态。
- 自由现金流近似值、每股自由现金流和市价自由现金流比。
- 存货增长与营业收入增长对比。
- 税前利润率及历史、同行百分位。
- 内部人士交易、已注销回购和股本稀释。
- 资本行为真实资金评分。

林奇增长估值比只使用以下解释：

- 小于1：较差。
- 约1.5：可以接受。
- 大于或等于2：良好。

不得自行增加1至1.5之间的新评级。

#### 支柱二：主营业务

展示：

- 主营业务名称。
- 利润贡献金额。
- 利润贡献比例。
- 判断依据：分部利润或毛利润。
- 数据状态。

业务判断规则：

- 所有业务均披露分部利润时，以分部利润最高者为主营业务。
- 所有业务均未披露分部利润时，才允许使用毛利润。
- 只有部分业务披露分部利润时，状态必须显示为“无法确定”，不得混用。

#### 支柱三：流通市值

展示：

- 流通市值。
- 在正常A股中的流通市值百分位。
- 市场横截面日期。
- 有效样本数量。

流通市值用于观察股票能否形成较充分的多空博弈，不代表股票质量。

#### 支柱四：讨论热度与情绪

分别展示东方财富股吧、雪球和两平台综合结果：

- 原创用户帖子数量。
- 点赞加权热度。
- 平台内热度百分位。
- 情绪值。
- 看多、看空和中性占比或数量。
- 实际数据日期。
- 帖子引用数量。

帖子权重公式：

```text
权重 = 1 + ln(1 + 点赞数)
```

只允许原创用户讨论进入计算，不允许公告、新闻、转载或转发内容进入计算。

### 4.3 板块候选池页

展示：

- 板块代码。
- 板块名称。
- 数据来源。
- 快照时间。
- 成分股数量。
- 成分股代码和名称。
- 快照是否完整。
- 抓取错误。

必须使用“板块候选池”或“候选板块”措辞。东方财富和同花顺板块只是发现股票的入口，不是正式策略板块，也不能自动生成买卖信号。

## 5. 建议补充的只读接口

接口路径可以结合现有 FastAPI（快速应用程序接口框架）结构调整，但返回字段必须来自真实后端模型。

### 5.1 板块候选池

```text
GET /api/fundamentals/board-candidates/latest
GET /api/fundamentals/board-candidates/{board_code}
```

### 5.2 个股月度基本面

```text
GET /api/fundamentals/securities/{symbol}/monthly/latest
GET /api/fundamentals/securities/{symbol}/monthly?limit=12
```

### 5.3 个股每日舆情

```text
GET /api/fundamentals/securities/{symbol}/discussion/latest
GET /api/fundamentals/securities/{symbol}/discussion?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD
```

### 5.4 基本面总览

```text
GET /api/fundamentals/overview
```

建议支持：

- `board_code`：按候选板块筛选。
- `search`：按股票代码或名称搜索。
- `sort_by`：选择允许排序的字段。
- `sort_order`：升序或降序。
- `limit` 和 `offset`：分页。

接口不得在请求期间启动爬虫或执行大规模财务计算。页面只读取已经生成的快照。

## 6. 展示规则

### 6.1 缺失值

缺失值不得显示为0。应根据状态显示：

- 暂无数据。
- 数据不足。
- 不适用。
- 无法确定。
- 等待另一平台数据。

### 6.2 日期

每个区域必须展示实际数据日期，不得只显示页面加载时间：

- 月度基本面快照日期。
- 财报截止日期。
- 流通市值横截面日期。
- 舆情实际日期。
- 板块候选池快照时间。

### 6.3 百分位

百分位统一显示为0%至100%，同时保留后端原始精度。前端只负责格式化，不得重新计算。

### 6.4 评分

系统唯一允许展示的评分是资本行为“真实资金评分”。其公式由后端计算，前端不得重算：

```text
50
+ 内部人士交易调整（-30至30）
+ 已注销回购奖励（0至20）
- 股本稀释惩罚（0至20）
```

不得把该评分命名为“基本面评分”或“股票总分”。

## 7. 前端交互要求

- 股票代码和名称均可搜索。
- 点击候选板块后只显示其成分股。
- 点击股票进入四支柱详情。
- 支持查看最近12个月度快照。
- 支持查看最近30天舆情趋势。
- 数据缺失时页面仍应正常渲染。
- 部分平台舆情缺失时分别展示已有平台，但综合值必须显示“等待另一平台数据”。
- 错误信息应面向用户表达，不直接展示程序堆栈。
- 页面不得提供自动买入、自动卖出或投资建议。

## 8. 自动化验收标准

必须新增基本面浏览器端到端测试，至少覆盖：

1. 用户可以打开基本面总览页。
2. 用户可以选择候选板块并看到对应股票。
3. 用户可以搜索股票并打开详情页。
4. 四个支柱均能使用样例数据正常渲染。
5. 缺失字段不会被显示为0。
6. 部分分部利润披露时显示“无法确定”。
7. 存货状态可以区分“可用”“数据不足”“不适用”。
8. 只有一个舆情平台有数据时不生成综合值。
9. 页面不显示基本面总分。
10. 现有页面和测试不发生回归。

完整验收命令：

```bash
npm run typecheck
npm test
```
