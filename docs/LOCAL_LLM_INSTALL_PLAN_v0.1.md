## 2. 本次申请批准的范围

第一阶段只安装和下载：

1. Ollama 本地模型运行框架；
2. `qwen3:14b`，官方 Ollama 模型库的 Q4_K_M（四位混合量化）版本；
3. 工程调用 Ollama 所需的最小 Python 客户端依赖调整；
4. 30 个历史案例测试所需的本地配置和结果目录。

第一阶段明确不安装：

- Qwen3.5-9B；
- Qwen3.6-27B；
- MLX-LM；
- llama.cpp；
- Docker 模型服务；
- 云端模型、外部模型接口或需要密钥的搜索接口；
- 登录、付费或需要浏览器会话的新闻来源。

9B 只有在 14B 基线测试完成后，另行提交第二阶段下载确认。27B 只有前两款不能满足验收或确需能力上限测试时，另行确认。

## 5. 安装位置和数据位置

建议：

- Ollama 应用使用官方 macOS 发行版；
- Ollama 模型使用其默认本地模型目录；
- 不把模型权重、缓存或运行日志写入 Git；
- 工程只保存模型标识、修订、量化、运行框架版本、配置和必要结果；
- 证据原文件与模型权重分别存放，不能混入 `contracts/` 或源代码目录。

安装前再次显示最终应用路径和模型目录；如实际安装器要求创建命令行链接或登录启动项，必须单独说明，不能静默接受。

## 6. 自启动策略

第一阶段测试不启用新的登录自启动项：

- Ollama 在需要测试时手动启动；
- 不修改现有 Fourseasquant LaunchAgent（用户后台启动代理）；
- 不禁止 Mac 休眠；
- 生产事件监控和 Ollama 生命周期接入，等模型通过验收后再设计和批准。

## 7. 安装后验证

安装完成不等于可用，必须实际验证：

1. Ollama 版本、进程和回环监听地址；
2. 模型文件标签、量化、大小和哈希/清单状态；
3. 8K 上下文单请求；
4. 工具调用参数；
5. JSON Schema（结构化数据约束）输出；
6. 模型卸载后统一内存是否释放；
7. 峰值统一内存和交换内存；
8. 首字延迟、生成速度和完整事件耗时；
9. 现有 FastAPI、SQLite 和前端同时运行时是否稳定；
10. 不访问局域网或公网监听地址。

验收记录建议保存到：

```text
outputs/local-llm-benchmark/
```

目录只保存配置、指标和结构化结果，不保存模型文件或完整媒体正文。

## 8. 模型任务验收线

- 未来信息泄漏、范围外股票或虚构来源：0 次；
- 候选符合主营、供需和证据规则：不低于 90%；
- 应形成候选的事件中，前 3 至少包含 1 只正确受益龙头：不低于 80%；
- 结构化结果最多一次纠正后有效率：100%；
- 高优先级事件 20 分钟内完成：不低于 95%；
- 应空选时不得强行选股；
- 不长期使用交换内存，不影响现有工程服务。

## 9. 回退与清理

若第一阶段模型不合格：

- 停止 Ollama 模型服务；
- 删除 `qwen3:14b` 模型权重，保留测试配置和结果；
- 不删除历史证据、用户反馈或规则文件；
- Ollama 应用是否保留，等 9B 或其他运行框架方案确认后决定；
- 不使用破坏性命令清理整个模型目录。

模型通过后，也不立即启用生产监控；先完成来源适配、工具白名单、不可修改快照和 30 例测试。

## 10. 用户批准项

用户批准本清单只代表允许执行第一阶段：

> 安装 Ollama，下载 `qwen3:14b` Q4_K_M，最多使用约 15GB 新增磁盘，按单模型、单请求、8K/16K 上下文完成历史案例和内存测试。

它不授权下载 9B、27B，不能启用新的登录自启动，不能接入付费或需要密钥的服务，也不能删除其他用户数据。
