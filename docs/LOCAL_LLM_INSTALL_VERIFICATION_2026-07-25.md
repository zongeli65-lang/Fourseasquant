## 3. 实测结果

### 3.1 服务与硬件

- 服务版本接口返回 0.32.3；
- 监听日志确认地址为 `127.0.0.1:11434`；
- 最终配置日志确认 `OLLAMA_NO_CLOUD=true`，即禁用 Ollama 云端模型；
- 推理后端识别为 Apple M5；
- 计算接口为 Metal（苹果图形计算接口）；
- `ollama ps` 显示模型 100% 使用 GPU（图形处理器）；
- 不显式传入上下文长度的最小请求，实际仍按 8192 加载，证明工程默认值生效。

### 3.2 结构化输出

使用虚构供需事件和虚构公司进行验证：

- 上下文：8192；
- 温度：0；
- 输出约束：JSON Schema（结构化数据约束）；
- 结果：一次成功，字段完整且没有额外字段；
- 模型正确识别“主营收入占比 70% + 供需正向传导”，并只形成候选判断，没有作最终投资决定。

首次运行指标：

| 指标 | 实测值 |
|---|---:|
| 模型加载 | 约 5.42 秒 |
| 完整请求 | 约 16.51 秒 |
| 输入处理 | 约 122.02 token/s（词元/秒） |
| 输出生成 | 约 8.44 token/s（词元/秒） |

### 3.3 工具调用

给模型提供 `query_local_company_evidence` 公司证据查询工具，并要求判断虚构证券代码 `600001`：

- 模型没有直接编造公司事实；
- 返回了工具调用；
- 参数包含证券代码；
- 请求证据字段为“主营业务”和“收入占比”；
- 暖机后的完整工具调用请求约 5.88 秒；
- 输出生成约 8.60 token/s（词元/秒）。

这只证明模型能够正确提出工具请求，不代表真实公司证据适配器已经接入。

### 3.4 统一内存

模型以 8K 上下文加载时：

| 指标 | 实测值 |
|---|---:|
| Ollama 显示模型占用 | 10GB |
| 图形处理器占比 | 100% |
| K/V 缓冲区 | 1280MiB，f16 |
| 系统报告可用内存比例 | 约 22% |
| 交换空间 | 0 |

模型完全卸载后：

| 指标 | 实测值 |
|---|---:|
| `ollama ps` | 空 |
| 系统报告可用内存比例 | 约 66% |
| 交换空间 | 0 |

结论：这台 24GB 统一内存的 M5 可以稳定运行 Qwen3-14B Q4_K_M 的单请求 8K 基线；必须维持单模型、单请求并在不用时卸载。16K 仍需单独做压力测试，不能把本次结果外推为已通过。
