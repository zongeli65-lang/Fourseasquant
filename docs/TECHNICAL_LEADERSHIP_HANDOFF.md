# 技术龙头评分与板块选举交接

## 1. 目标

本模块只负责量价技术分析，不读取财报、研报、财经软件简报或基本面结论。它为沪深主板、创业板和科创板的合格股票生成唯一的日频技术分，并在获得基本面模块发布的板块成员关系后，重放板块技术龙头选举。

正式综合龙头不在本模块内确认。未来融合层需要把技术龙头结果与独立基本面评分连接。

## 2. 四层架构

1. 个股技术评分模块：完全独立于板块归属，对每只股票计算 0—100 分。
2. 基本面板块模块：根据财报、公司与行业研究、简报和快报发布板块成员关系与基本面评分。
3. 板块技术选举模块：连接成员关系与个股技术分，执行前五候选、保位、挑战、确认和失效。
4. 综合龙头融合层：未来结合技术与基本面结果，确认正式综合龙头。

市场趋势状态由核心策略提供；板块成员关系由基本面模块提供，二者不得互相替代。

## 3. 技术评分定义

价格函数使用前复权收盘价的 3 日 EMA（指数移动平均）：

```text
f[t] = 0.5 * close[t] + 0.5 * f[t-1]
```

离散一阶导数为 `f[t] - f[t-1]`。导数绝对值不超过 `0.10 × ATR(10)` 时进入自适应零区间。导数由正转负确认局部最大值，由负转正确认局部最小值。

候选上升结构要求相邻两次最大值形成一次有效抬升，同时相邻两次最小值也形成一次有效抬升；最大值和最小值各连续出现两次有效抬升（三个极值）时记为强结构。极值差值除以 ATR(10) 标准化，单次按 3 倍 ATR 封顶，连续结构可以累计。

分项权重：

| 分项 | 分值 |
|---|---:|
| 极值结构 | 55 |
| 进行中突破 | 20 |
| 3、5、10 日相对强度 | 15 |
| 成交确认 | 10 |

相对强度同时比较沪深 300及所属市场指数。主板按交易所使用上证指数或深证成指，创业板使用创业板指，科创板使用科创 50。

## 4. 选举规则

- 每个板块至少需要 3 只有效成员。
- 全量技术结果永久保存，对外衔接前 5 名。
- 结构不完整的短期突破股票只能是观察候选。
- 新成员与趋势切换后的候选需要连续 2 日确认。
- 原龙头软转弱时，挑战者需满足分差和确认期。
- 市场趋势切换、成员移除、数据失效或结构明确破坏属于硬失效，立即撤销。
- 同一股票可以领导多个板块；这些板块共享同一技术强度，汇总时应按龙头代码去重。
- 上升、下降和震荡市场都可以产生技术龙头，但分别标记为顺势、逆势或震荡期龙头。

## 5. 初始化与每日执行

正式结果覆盖最近一年，另取正式起点前 60 个交易日作为预热数据。预热只用于建立 EMA、导数和极值状态，不对外展示。

初始化命令：

```zsh
cd /Users/lz666/Documents/quant/fourseasquant-t01
npm run data:technical-init
```

若完整行情已经存在，可只重建评分：

```zsh
uv run python scripts/initialize_technical_scores.py --skip-market-refresh
```

行情初始化采用严格完整批次。网络失败或历史缺失不能伪装成业务排除；任务支持按股票断点续跑，只有完整批次才能发布。

### 5.1 网站全市场查询

总览页继续调用 `/api/technical-scores/top` 展示前 5 名。策略页调用：

```text
GET /api/technical-scores
```

支持 `target_date`、`page`、`page_size`、`search`、`board`、`sort_by`
和 `sort_order`。每页最多 100 只，搜索同时匹配六位代码和中文名称。

响应将目标日有评分的股票与目标日缺行情的股票明确分开：

- `current_score_count`：进入目标日正式排名的股票数；
- `stale_score_count`：目标日没有评分、但存在历史评分的股票数；
- `rank`：仅目标日评分具有正式名次；
- `is_current=false`：页面显示最近评分日期，不与目标日排名混算。

筛选、搜索和排序均在后端完成，前端不一次性加载全市场复杂证据。

## 6. 基本面任务衔接

基本面新任务应先阅读完整的
[`FUNDAMENTAL_ENGINEERING_HANDOFF.md`](FUNDAMENTAL_ENGINEERING_HANDOFF.md)，
并在决定数据来源、评分体系和发布流程前使用 `$grill-me` 与用户完成需求访谈。

基本面任务必须发布 `SectorMembershipSnapshot`，字段采用英文，示例位于：

```text
contracts/examples/sector-membership.example.json
```

机器校验规范：

```text
contracts/sector-membership.schema.json
contracts/sector-leadership.schema.json
```

成员关系必须包含版本、生效日期、变更原因和证据引用。技术模块拒绝 `complete=false` 的残缺快照。若当天基本面更新失败，选举层应沿用最近一次完整成功版本并标记版本陈旧；从未存在完整快照时不得生成真实板块技术龙头。

## 8. 参数与版本

前端只读，不允许修改技术参数或人工指定龙头。参数只能从后端修改，并必须生成新版本。历史重算需显式指定日期范围，新旧版本结果不得互相覆盖。

初始版本为 `technical-v1`。默认正式门槛、挑战分差和导数零区间系数需要使用确认后 3、5、10 日持续表现进行离线校准。未来数据只能用于评估参数，实时评分严格只使用当日及以前数据。
