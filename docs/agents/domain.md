# 领域文档

工程技能在检查或修改代码前，应按以下规则读取领域文档。

## 开始检查前

- 读取仓库根目录的 `CONTEXT.md`。
- 如果根目录存在 `CONTEXT-MAP.md`，按映射读取与任务相关的上下文文档。
- 读取 `docs/adr/` 中与当前工作相关的架构决策记录。

如果这些文件尚不存在，继续工作即可，不要仅因为缺失而提前创建。需要确定领域术语或重要决策时，再由领域建模流程按需生成。

## 文件结构

本仓库采用单上下文结构：

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
└── src/
```

## 术语规则

问题标题、重构提议、测试名称和代码概念应使用 `CONTEXT.md` 定义的术语。不要改用词汇表明确排除的同义词。

如果需要的概念尚未定义，应先判断是否使用了不属于本项目的语言；如果确实存在领域空缺，再交给领域建模流程处理。

## 架构决策冲突

如果计划与已有架构决策记录冲突，必须明确指出冲突，不得静默覆盖。例如：

> 这与 ADR-0007 的既有决定冲突，但由于……，值得重新评估。
